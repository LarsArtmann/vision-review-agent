00Critical Discovery: The ROADMAP Premise Was Wrong

The original question

"catwalk or hand-rolled CLI providers? The three providers added to cmd/vision/main.go (Anthropic, Google, openaicompat) work but will rot as fantasy evolves. Replace them with github.com/charmbracelet/catwalk."

This implies catwalk IS a provider factory. It is NOT.

What catwalk actually is (verified from source)

charm.land/catwalk is a model metadata catalog — a database of AI providers and their models. It ships:

  • pkg/catwalk — Types (Provider, Model, Type, InferenceProvider) + an HTTP Client with ETag caching
  • pkg/embedded — Offline catalog compiled into the binary (embedded.GetAll() []catwalk.Provider)
  • 40+ inference providers with model metadata: capabilities, pricing, context windows, reasoning support

Provider construction still uses fantasy (openai.New(), anthropic.New(), etc.). Crush's coordinator.go:buildProvider() switches on providerCfg.Type (from catwalk) to call the right fantasy constructor — exactly the bridge pattern this project should adopt.

The real value proposition: Not "replace provider code" but add model discovery, capability awareness, pricing data, and auto-update. The CLI goes from 5 hardcoded providers to 40+ catalog-driven providers with vision filtering, cost tracking, and model validation — all from a single dependency.

Data flow: CLI analysis with catalog

User runs:
  vision -provider openai -model gpt-4o screenshot.png

1. catalog.New()
     → embedded.GetAll() or remote sync (if CATWALK_URL set)

2. catalog.FindProvider("openai")
     → catwalk.Provider{Type: TypeOpenAI, APIKey: "OPENAI_API_KEY", ...}

3. catalog.FindModel("gpt-4o")
     → catwalk.Model{SupportsImages: true, CostPer1MIn: 2.5, ...}

4. BuildProvider(provider, apiKey, baseURL)
     → switch provider.Type
     →   case TypeOpenAI: return openai.New(openai.WithAPIKey(apiKey))

5. vision.NewAgent(Config{
       Model:     languageModel,
       ModelInfo: &vision.ModelInfo{...},  # NEW
   })

6. agent.Analyze(ctx, prompt, images...)
     → MaxOutputTokens from ModelInfo if unset
     → Hooks.OnFinish → CostTracker.AddResult + CostUSD()
Design constraint: The adapter from catwalk.Model to vision.ModelInfo lives in pkg/vision/modelinfo.go, NOT in internal/catalog. This means pkg/vision must import charm.land/catwalk/pkg/catwalk. This is acceptable — catwalk is a metadata library with no runtime dependencies beyond stdlib + charmbracelet/x/etag. The alternative (duplicating all fields) violates DRY.
