The Goal

A systemd-managed daemon (visionreviewd, built here on top of pkg/vision) that watches UI screenshots across ALL projects, reviews every view with llama-server -hf GitMylo/nsfwcaption-qwen3-vl-8b-v3-gguf:Q8_0, writes per-view .md reviews plus a per-project INDEX.md into a dedicated reviews directory, records everything as events (go-cqrs-lite, bbolt), and auto-runs BEFORE→AFTER comparisons when a view changes — so Crush can be pointed at the reviews dir and asked to make the project better.

Why this repo drifted

The project became a general-purpose vision SDK (pkg/vision + catalog-driven CLI) instead of the UI review daemon it was meant to be. The SDK is exactly the right foundation — the daemon is the missing application layer on top of it (cmd/visionreviewd + internal/reviewd).

02Architecture

Single Go binary visionreviewd. Poll loop scans configured screenshot globs, hashes files (sha256), and treats each project:Page--theme--viewport as an event-sourced View stream. New hash → view.captured → review via llama-server → view.reviewed → markdown written. Changed hash with a predecessor → A/B comparison → view.compared. Markdown lives in the event payloads, so replay can rebuild the whole reviews directory from the event log without touching the model.

Event Model

Event Payload Emitted when
view.captured SourcePath, SHA256, CapturedAt scan finds a hash not yet seen for the View stream
view.reviewed SHA256, Model, Markdown, Score 0-10, ReviewedAt model finished reviewing the current capture
view.compared BeforeSHA, AfterSHA, Model, Markdown, ReviewedAt capture changed and a previous capture exists

Reviews Directory (the Crush entry point)

reviews/ ├── discordsync/INDEX.md ├── discordsync/views/Settings--dark--desktop.md └── discordsync/comparisons/2026-08-16_Settings--dark--desktop.md

CLI Surface

Command Purpose
run daemon loop: scan → ingest → review → compare → write → sleep
review one-shot full pass (no sleep); -project/-view filters
compare <a> <b> manual two-image A/B ("what improved, what got worse")
events pretty-print event history per project/view
replay rebuild entire reviews dir from the event log
discover scan ˜/projects for screenshot patterns, print suggested config
doctor validate config, dirs, llama-server reachability, model id

05Risks & Decisions

No structured/tool JSON mode on llama-server

fantasy's object mode uses tool calling, which local llama-server may handle poorly. Decision: plain Analyze with prompt-engineered markdown output; score parsed from a Score: N/10 line. Robust for ANY local model.

Port 8080 already occupied on this machine

Verified: something already listens on *:8080 (not llama-server; /v1/models 404s). Default base URL stays llama-server's default for manual runs, but the NixOS module takes an explicit port (register one in SystemNix lib/ports.nix) and doctor detects mismatches.

go-cqrs-lite must resolve via the Go module proxy

Submodule tags exist locally (storage/v4.7.1, decider/v4.3.0). If GitHub tags lag, fall back to a documented replace to the local checkout with a TODO to publish — never silently pin a path.

SystemNix must stay green (no push from this session)

SystemNix consumes only pushed GitHub revs. The wrapper module is written fully lazy (inputs referenced only under mkIf cfg.enable, no imports), so it evaluates safely while disabled; activation steps are documented in the module header.

Real-model smoke test deferred

The Q8_0 8B model (~9–10 GB) is not in the HF cache and port 8080 is dead. E2E confidence comes from a fake OpenAI-compatible server over real HTTP; doctor + docs cover the real-model bring-up.
