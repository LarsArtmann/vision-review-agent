## e) WHAT WE SHOULD IMPROVE

1. **Exit-code discipline**: never trust `$?` after a pipe; standardize on `${PIPESTATUS[0]}` (or run unpiped) for every gate command. Two false greens in one session is two too many.
2. **Shared-tree coordination protocol**: auto-daemon + parallel sessions made `edit` refuse 4 times and nearly duplicated declarations. Cheap fix: before editing a file not touched in the last N minutes, `git log -1 --format=%ci -- <file>`; better: an agreed ownership manifest per session (which session owns which WP's files).
3. **Verify-then-document, never the reverse**: the vendor-guard incident (d1) happened because docs updated ahead of the full suite. The new norm (command + date) should explicitly include "full suite green BEFORE any claim about a guard/wider walk".
4. **Sanctioned gates over hand-rolled ones**: run `dep-drift` + `verify-bump` for every bump, even when I "know" the steps — they encode gotchas (vendor re-sync!) my ad-hoc matrix initially missed.
5. **LSP panel vs CLI**: the panel produced 12 stale/false warnings against CLI-0 even after restart. Consider disabling `golangci_lint_ls` in crush config for this repo (keep gopls) — the noise cost now exceeds the signal.
6. **Fuzz reporting**: a tiny runner script (`scripts/fuzz-a2ui.sh`) recording per-target execs/durations, CI-dispatchable, so fuzz receipts are uniform.
7. **Status-report cross-session sync**: the [parallel] session landed three of "my" gated WPs (D1/D3/watchdog) while I worked; a 30-second `git log --grep` check at session start would have re-planned around it sooner (I caught most of it mid-flight, late).
